# 13 — n8n Audit

Phase 1, read-only. Evidence: `docker inspect`, `n8n export:workflow --all` (130 workflows, read-only CLI export, no activation), Caddy proxy config in front of n8n, bare-repo git log/README at `/opt/codestra/n8n-workflows-authoritative.git`. No workflow was activated or executed.

## Facts

- **Version:** n8n `2.30.8` (image `n8nio/n8n`, pinned by digest).
- **Deployment mode:** Single/main mode. No `EXECUTIONS_MODE=queue` or `QUEUE_BULL_REDIS_*` env vars on the production `codestra-n8n-1` container. A prior attempt at queue-mode ("codestra-n8n-runtime-canary-*", "codestra-n8n-runtime-worker-*", ~10 containers) exists but all instances are **exited, ~2 weeks old** — an abandoned or superseded effort, not the current architecture.
- **Backing store:** Postgres, but **not a dedicated n8n database instance** — it's database `codestra_n8n` on the shared main `codestra-postgres-1` container, role `n8n_app`. Redis (`codestra-redis-1`) exists but is not wired to n8n in this mode (Redis is likely used by the middleware, not n8n, in single mode).
- **Staging parallel stack:** A full separate `codestra-n8n-staging-*` project runs main+webhook+2 workers+redis+postgres — genuine queue-mode staging environment, correctly isolated from production by network (`codestra-n8n-staging_backend`, `codestra-n8n-staging_edge`).
- **Ingress:** `codestra-n8n-internal-proxy` (hardened Caddy) fronts n8n with: IP allowlist restricting non-`/healthz`/`/readyz`/attestation/`@events` paths to `$INTEGRATION_CIDR` (default `10.254.41.0/28`), a dedicated `/webhook/codestra/v1/events` path with a 256KB body cap, and a `.well-known/codestra-target/v1` attestation endpoint proxied to the middleware. This is a genuinely hardened edge — good practice.
- **Retention/limits:** `EXECUTIONS_DATA_MAX_AGE=336` (14 days), `EXECUTIONS_DATA_PRUNE=true`, `N8N_RUNNERS_TASK_TIMEOUT=300`s, `N8N_COMMUNITY_PACKAGES_ENABLED=false`, `N8N_PUBLIC_API_DISABLED=true`, `N8N_UNVERIFIED_PACKAGES_ENABLED=false`, `N8N_SECURE_COOKIE=true` — conservative, security-conscious defaults.
- Kill-switch flags also present on the n8n container itself: `LIVE_PSTN_DIALING=false`, `LIVE_EMAIL_DELIVERY=false`, `LIVE_SMS_DELIVERY=false`, `EXTERNAL_DELIVERY_ENABLED=false` — consistent with the platform-wide `live-delivery-admission.sh` pattern documented in `12_SMS.md`.

### Finding N8N-P1-01 — 129 of 130 workflows are inactive; the platform has effectively zero live automation
**Severity:** P1 (production blocker — but deliberate, documented, in-progress)
**Component:** n8n workflow activation state
**Observed evidence:** `n8n export:workflow --all` → 130 workflows. `jq '[.[]|select(.active==true)]|length'` → **1**. The single active workflow, `External Webhook Certification Sink V1`, contains only a `webhook` trigger and a `code` node — a certification/test sink, not a business process. Every workflow that implements a described business capability is inactive, including: all `CP-17` through `CP-37` event-contract workflows (SMS/email/CRM lifecycle events), all `CDST_*` workflows (campaign routing, lead assignment, callbacks, appointments), all `WF-00` through `WF-90` numbered pipeline stages (call lifecycle, callback management, lead intelligence, sales/hot-leads, agent/queue monitoring, QA/compliance, reporting, error/dead-letter), and every vertical-specific workflow (`moneybee_*`, `student_*`, `senior_*`, `transportation_*`, `codestra_*`).
**Root cause (documented, not inferred):** The authoritative workflow source repo (`/opt/codestra/n8n-workflows-authoritative.git`, HEAD README) states this is explicit "Sprint 1" policy: *"Live import is permitted only after every isolated gate passes. Imported workflows must remain `active=false`; no trigger may be activated or executed during Sprint 1."* Latest commit: `985a8b5 Document staging workflow source authority`.
**Expected state (mission Step 23):** Working Odoo↔SMS/Email↔n8n round trips.
**Current state:** n8n is present, healthy, and correctly wired at the infrastructure level, but performs **no live business automation**. Every mission acceptance journey that routes through n8n (SMS, Email, most of the call lifecycle's async fan-out) fails at this hop today.
**Risk:** None to current production (nothing can misfire since nothing is active) — but this is the single largest gap between "documented architecture" and "actually running system" found in this fork's scope. Any Phase 2 plan must treat "activate and verify each workflow class" as major, sequenced work, not a checkbox.
**Recommended fix:** Build the go-live plan around the existing Sprint-1 gating: define the isolated-gate criteria referenced in the README, verify each, then activate workflows in controlled batches (e.g., start with `N8-00 Global Error Handler` and `WF-90_ERROR_AND_DEAD_LETTER`, then one business vertical at a time), each with its own before/after evidence capture.
**Test required:** Per-workflow activation test in staging (`codestra-n8n-staging-*` stack already exists for exactly this) before any production activation.
**Repository:** `/opt/codestra/n8n-workflows-authoritative.git` (bare, on-host — **confirm whether this is mirrored to GitHub**; not seen in the `appolon1908-hue` repo list reviewed earlier in this audit — flag to `03_GITHUB_RUNTIME_RECONCILIATION.md` as possibly Git-invisible production config).
**Suggested branch:** `feat/n8n-sprint2-activation-plan`

### Finding N8N-P2-01 — n8n is not (currently) acting as a system of record
**Severity:** informational / confirms compliance with mission constraint
**Observed evidence:** No workflow in the export writes to a database node or holds durable business state beyond n8n's own execution log; `EXECUTIONS_DATA_PRUNE=true` with 14-day retention confirms execution history is treated as ephemeral, not authoritative. This is correct per the mission's "n8n must not become the authoritative system of record" requirement — **no finding required**, stated for completeness.

### Finding N8N-P3-01 — Abandoned queue-mode migration artifacts left on host
**Severity:** P3 (hygiene)
**Observed evidence:** ~10 exited containers named `codestra-n8n-runtime-canary-*`/`-worker-*` with content-hash image tags, all 2 weeks old, none running.
**Recommended fix:** `docker rm` the exited canary containers (Phase 2, not Phase 1) once confirmed genuinely abandoned rather than paused; low risk, pure cleanup.

## Verdict for this domain
Infrastructure (version, security posture, edge hardening, retention policy, staging isolation) is solid. **Business functionality is present in code but universally inactive by explicit, documented policy.** This is the most consequential single finding across email/SMS/n8n: nothing downstream of "an event happened" currently executes.
