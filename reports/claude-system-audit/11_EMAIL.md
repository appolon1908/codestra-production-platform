# 11 — Email System Audit

Phase 1, read-only. Evidence gathered from `codestra-app` host only (docker inspect, Odoo `ir_mail_server`/`ir_cron` read-only SELECTs, container filesystem greps, passive DNS lookups). No email was sent.

## System Map (as found, not as documented)

Multiple, only loosely related email components run under the `codestra-*` compose namespace. They are **not** a single coherent adapter chain:

| Component | Container | Role (evidence-based) |
|---|---|---|
| `codestra/mail-api` | `codestra-mail-api-mail-api-1` | Mailbox **provisioning** API (OIDC-protected, SQLite registry at `/var/lib/codestra-mail/registry.db`). Not a sending path. |
| Stalwart v0.16 | `codestra-mail-isolated-stalwart-1` | Full MTA/IMAP/POP3/ManageSieve, bound to an **isolated** private network (`codestra-mail-isolated_mail-private`), ports only on 127.0.0.1. | `codestra-email-reseller-api` | `codestra-email-reseller-api-1` | Reseller/tenant-provisioning API (see `/root/codestra-odoo-middleware-functional/email_reseller_service`, `reports/EMAIL_RESELLER_CERTIFICATION_20260816.md`). Distinct product surface from transactional send. |
| `codestra/beyvra-email` | `codestra-beyvra-email-api-1` | **Proxies sends to `https://klyrow.internal.codestra.agency/v1/internal/email/send`** (`KLYROW_SEND_URL` env var), mTLS-authenticated. `LIVE_EMAIL_DELIVERY=false`. ### Finding EMAIL-P1-01 — Odoo emails bypass the middleware entirely
**Severity:** P1 (production blocker / architecture violation)
**Component:** Odoo ↔ Middleware boundary
**Observed evidence:** `ir_mail_server` (Postgres `codestra_odoo` DB) contains a single outgoing mail server, `Klyrow Postal SMTP`, host `mail.klyrow.com`, port 25. Odoo's native mail-queue cron (`Mail: Email Queue Manager`) would, if active, deliver directly to this external SMTP relay — no middleware, no `codestra/mail-api`, no adapter, no audit event, no correlation ID.
**Expected state (mission spec):** `Odoo → Middleware → Email adapter → Email provider/MTA → Recipient`.
**Current state:** `Odoo → (direct SMTP) → mail.klyrow.com`, a relay owned by a different, out-of-scope product (Klyrow). No middleware involvement, no idempotency/audit layer on this path.
**Risk:** Untracked, unaudited outbound email; no delivery/bounce reconciliation into the middleware's durable inbox; cross-tenant dependency on infrastructure this audit was told is out of scope; DMARC/SPF alignment depends entirely on a third party's relay behavior.
**Files:** Odoo `ir_mail_server` table (DB `codestra_odoo`), `/opt/codestra/odoo` addons.
**Recommended fix:** Route Odoo outbound mail through the middleware's email adapter (or explicitly document Klyrow-Postal-direct as the accepted architecture and add audit/correlation instrumentation at that boundary).
**Test required:** Send a non-production test email through Odoo compose, verify it appears in middleware's outbox/audit log before/instead of going straight to Klyrow.
**Rollback:** N/A (read-only finding).
**Repository:** likely `codestra-production-platform` (Odoo addon config) — unconfirmed which repo owns `ir_mail_server` seed data.
**Suggested branch:** `fix/odoo-email-through-middleware`

### Finding EMAIL-P1-02 — Odoo's own mail queue processing is disabled
**Severity:** P1
**Component:** Odoo scheduled actions (`ir.cron`)
**Observed evidence:** Read-only query of `ir_cron` in `codestra_odoo`: `Mail: Email Queue Manager` — **active=false**; `Mail: Post scheduled messages` — **active=false**; `Mail: Fetchmail Service` — **active=false**; `SMS: SMS Queue Manager` — **active=false**. Only `Mail Marketing: Process queue` is active.
**Expected state:** Core mail-queue cron active so any mail Odoo generates (invoices, notifications, CRM notifications) is actually delivered.
**Current state:** Mail generated by Odoo (outside the marketing module) queues in `mail.mail` and is never flushed automatically.
**Risk:** Silent mail non-delivery for transactional/CRM notifications; easy to mistake for "email works" because compose/send succeeds at the UI layer while delivery never happens.
**Recommended fix:** Confirm whether disabling these crons was deliberate (e.g., pending the middleware cutover) — if not, re-enable `Mail: Email Queue Manager` before go-live.
**Test required:** Enable cron in staging, send a test transactional email, confirm delivery.
**Repository:** `codestra-production-platform` (Odoo config/data).
**Suggested branch:** `fix/odoo-mail-queue-cron`

### Finding EMAIL-P2-01 — DMARC not enforced on primary sending domain
**Severity:** P2
**Component:** Email DNS
**Observed evidence:** `dig TXT _dmarc.codestra.agency` → `v=DMARC1; p=none; rua=mailto:dmarc@codestra.agency; adkim=s; aspf=s; pct=100`. Policy is `p=none` (monitor-only).
**Expected state:** `p=quarantine` or `p=reject` once SPF/DKIM alignment is confirmed stable.
**Current state:** Spoofed mail from `codestra.agency` would not be rejected/quarantined by receivers honoring DMARC.
**Note:** `codestra.co`'s DMARC is `p=quarantine` with `rua=mailto:dmarc_rua@onsecureserver.net` (a GoDaddy-managed address, not a Codestra-owned mailbox) — inconsistent domain governance between the two primary domains.
**Repository:** DNS is provider-managed, not in Git — flag as infra config drift.

### Finding EMAIL-P2-02 — No DKIM record found under `default` selector
**Severity:** P2 (UNVERIFIED — selector name not confirmed)
**Observed evidence:** `dig TXT default._domainkey.codestra.agency` and `...codestra.co` both empty.
**Caveat:** Only the `default` selector was checked; Postal/Klyrow may use a different selector (e.g. `postal`, `s1`). **Mark UNVERIFIED** — needs the actual selector from Klyrow's Postal config to confirm DKIM is (or isn't) published.

### Finding EMAIL-P3-01 — Both MX records point to Klyrow, not a Codestra-owned host
**Severity:** P3 (architecture note, not necessarily a defect)
**Observed evidence:** `codestra.agency` and `codestra.co` MX both → `mail.klyrow.com`; SPF `include:spf.klyrow.com`.
**Risk:** Email deliverability, inbound routing, and bounce/complaint webhook reliability for the Codestra platform depend on infrastructure this audit was explicitly told is a separate product (Klyrow, host `codestra-provider`/10.40.0.4) and was excluded from direct inspection. This is a real dependency the mission's architecture diagram does not account for.

## Verdict for this domain
Email is **not** production-ready as an integrated Odoo→middleware→provider→bounce-loop system. What exists is several independently-built services (mailbox provisioning, reseller API, a Klyrow-proxying "Beyvra" API) plus Odoo talking directly to an external relay with its own queue processing disabled. Treat STEP 23's "Email" end-to-end journey as **FAIL**, not PARTIAL, pending EMAIL-P1-01 and EMAIL-P1-02.
