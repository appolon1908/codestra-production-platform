# SMS integration

Telnexa is the sole SMS adapter. Destinations must be E.164, marketing requires positive SMS consent, suppression is checked, and segment count is metered. Sender authorization, quotas, quiet hours, country rules, wallet reservation, and final Telnexa charges remain mandatory production policy/provider gates.

`TELNEXA_MODE=simulator` returns synthetic accepted IDs without network traffic. Production additionally requires both global gates, dedicated file-backed API-key and HMAC authorities, and the exact private HTTPS `/v1/messages` endpoint. The worker sends the gateway's canonical customer, tenant, message, recipient, content, correlation, and idempotency fields and never reuses the Klyrow OAuth/mTLS authority. A safe-mode gateway receipt is not promoted to carrier acceptance. Authenticated, attempt-bound carrier DLRs are atomically persisted with their governed control-plane projection, so a late rejection updates the originating ledger once forwarding is independently enabled. Provider events normalize into the ledger. `STOP` and `UNSUBSCRIBE` revoke consent and suppress SMS; `START` and `HELP` require an approved country/provider policy before automated effects.
